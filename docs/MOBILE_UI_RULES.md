# 手机端 UI 规则

> 手机端（宽度 < 768px）唯一的规则文档。新页面、改版和评审都以本文为准。
> 每条规则带编号（M1–M27），后面的标记说明由谁来保证：
> - **[lint]**：`npm run lint` 静态检查（`scripts/check-mobile-rules.mjs`）。
> - **[浏览器]**：`npm run test:mobile-rules` 浏览器检查（`scripts/browser-mobile-rules.py`）。
> - **[人工]**：评审时人工核对。
>
> 通用的桌面与设计令牌规则见 [UI_DESIGN_RULES.md](UI_DESIGN_RULES.md)，紧凑布局见 [COMPACT_LAYOUT_RULES.md](COMPACT_LAYOUT_RULES.md)。2026-10-08/09 的各轮实施记录已归档到 [history/mobile/](history/mobile/)，只作背景参考，与本文冲突时以本文为准。

---

## 1. 边界

- **M1** 断点：手机 < 768px，平板 768–1023px，电脑 ≥ 1024px。手机规则只能写在手机媒体查询里，或通过 `useErpPhone()` 分支实现，不得改变平板和电脑的呈现。[人工]
- **M2** 只改呈现，不改业务：手机端复用同一套路由、查询、表单控制器、校验、DTO 和写接口，不复制第二套业务表单、金额或库存算法，不新增或放宽权限。[人工]
- **M3** 只使用现有设计令牌（`tokens.css`），不另建手机主题、字体或配色。手机专用的尺寸令牌以 `--erp-mobile-*` 命名。[lint，由设计系统检查保证]

## 2. 尺寸与可读性

- **M4** 触控区域：普通按钮、输入框、选择器至少 44px 高；图标按钮至少 44×44px（图标 20px）；底部主操作和选项行至少 48px。这些都是最小值，长文字允许控件自然增高。[浏览器]
  - 例外：日期网格的单个日期格（宽度按七列平分）、表格内的排序和列宽手柄、状态标签（它们不是按钮），以及列表顶部横向滚动的状态筛选胶囊（`.erp-phone-chip`，36px，左右留足内边距）。
  - 按钮尺寸只能通过 `Button` 的 `size` 或全局令牌设置，页面里不得写内联高度（如 `style={{height: 42}}`）；禁用状态只改变透明度，不缩小点击区域。
- **M5** 可编辑输入框的字号 ≥ 16px，避免 iOS 聚焦时自动放大页面。[浏览器]
- **M6** 可见文字 ≥ 12px。层级：页标题 20/600，模块标题 16/500，正文 14/400，字段名 13/500，辅助信息 12/400。[浏览器，只检查下限]
- **M7** 页面不得出现横向滚动。表格和分类横条可以在自身容器内横向滚动。[浏览器]
- **M8** 商品全称、SN、关联单号可以完整换行；单号和金额不能在中间断开；金额不缩写成「万」，也不截断。状态标签不折行。[人工]

## 3. 导航

- **M9** 底部固定 5 个一级入口：首页、开单、库存、客户、我的。权限只决定入口是否显示，不另设手机专用的权限白名单。[人工]
- **M10** 底部高亮按「这个页面是从哪个 Tab 进入的」来决定，归属表维护在 `src/app/shell/mobileNavigation.ts`，修改时要同步更新对应测试。[人工，由单元测试守护]
- **M11** Tab 根页面（开单面板、我的）不显示返回箭头；二级全屏页面才显示返回。浏览器返回优先关闭最上层的浮层，然后回到上一个步骤，最后回到来源页。[人工]
- **M12** 「我的」包含全部已授权功能的分组列表和搜索，不重复列出「首页」，退出登录放在最底部。[人工]

## 4. 页面模板

所有页面都必须套用下面四种模板之一。参考实现是客户页：`src/features/customers/pages/CustomerDirectoryPage.tsx`。

> **模板组件（2026-10-10 起）**：列表页用 `ErpListPage`，详情抽屉内容用 `ErpRecordDetail`，开单页用 `ErpMobileWorkflow`。页面只提供数据（标题、计数、`ErpFilterField[]` 筛选、快捷筛选、主操作、表格），下面 M13 / M16 的结构由模板生成，页面里不再写 `useErpPhone` 分支。手机列表行优先在列定义上声明 `meta.mobile`（`title` / `subtitle` / `meta` / `amount` / `status` / `image` / `thumbnail`），表格传 `mobileRow="columns"`；电脑端单元格太复杂时用 `meta.mobileCell` 单独写手机显示。客户页 `CustomerDirectoryPage.tsx` 是第一个迁移完成的页面，其余页面按 [MOBILE_TEMPLATE_PLAN_20261010.md](MOBILE_TEMPLATE_PLAN_20261010.md) 分批迁移。

- **M13 列表页**（单据、库存、客户、商品、财务明细……）
  1. 页头：标题，下面一行小字显示结果数量（只在这里出现一次）；右侧放「筛选」按钮（`secondary` 样式，有生效筛选时显示数字角标）。
  2. `mobileToolbar`：左侧最多 4 个快捷筛选，右侧放排序按钮。
  3. 列表：`ErpDataTable` 传 `surface="plain"`、`mobilePagination="compact"`、`mobileRow`；每一行用 `ErpMobileRecordRow` 渲染，平铺成一整块白色列表面，行与行之间用细分隔线。
  4. 底部：`ErpMobileActionDock`，放搜索框，加上最多 1 个主操作。
  5. 高级筛选条件、每页条数、刷新入口都放进 `ErpDialogShell mobilePresentation="sheet"` 打开的筛选面板。
  - 功能页面使用 `ErpDataTable` 时必须传 `mobileRow`（函数或 `"columns"`），或者显式传 `mobileMode="table"` 并写明原因。[lint，由 `check-ui-contracts` 检查]
  - 手机上不得出现：刷新按钮、列设置 / 列显示、舒适 / 紧凑密度切换、「查看其余 N 项」、通用卡片（`data-erp-region="mobile-card-header"`）。[浏览器]
- **M14 开单页**（采购、销售、退货、编辑）：分成「客户 / 来源与商品 → 结算」两步，未显示的步骤保持挂载；每件商品用 `ErpMobileOrderLine` 编辑；底部用 `ErpSubmitBar` 显示合计和**唯一**的主操作；物流、质保、备注、附件折叠在结算步骤里。[人工]
- **M15 选择器**：少量固定选项用 `Select` 的底部菜单；需要搜索的内容（客户、商品、库存、单据）用全屏选择器，搜索区固定，只有结果区滚动；打开选择器时不自动弹出键盘。[人工]
- **M16 详情页**：顺序为「身份 / 状态 → 明细 → 结算 / 属性 → 补充信息」，字段用 `ErpDetailFact` 单列排列，少用卡片套卡片；只读记录不要做成看起来可以点击的样子。[人工]

## 5. 内容与文案

- **M17** 页面顶部的状态标签（`quickStatus`）只放**需要去处理的事**，并且最好能点击跳转到处理的地方（例如 待检测 → 质检）。系统信息（数据连接、筛选状态、各类权限、边界、回滚规则）不要做成标签。[lint]
- **M18** 数据卡每页最多一行、4 张；同一个数字不在标签、数据卡、横幅里重复出现；无数据时显示「—」，不要放占位卡（比如「成本信息：无权限」）。[lint 检查数量，人工检查重复]
- **M19** 文案用用户的语言。界面上不出现以下内容：服务端、服务器、接口（DP/HDMI 这类硬件接口除外）、租户、口径、已连接、由现有……负责、按当前筛选、当前筛选结果 / 汇总、内部菜单 ID、HTTP 状态码。[lint]
  - 权限不足统一写成：「当前账号没有……的权限，请联系管理员开通。」
  - 加载失败统一写成：「暂时无法读取……，请稍后重试。」
  - 删除限制直接说结果，比如「已有交易记录的客户无法删除。」
- **M20** 品牌名只从 `src/config/brand.ts` 读取，显示为「成都显卡一号店 · 进销存」；logo 只有 `public/favicon.svg` 一个，通过 `ErpBrandMark` 使用。不得出现「GPU ERP」「经营工作台」这类别名。[lint]
- **M21** 不编造数据：没有对应字段时，不显示状态徽章、示例金额或占位商品图；没有商品图片时显示品类图标。[人工]
- **M22** 金额为 0 用中性色；收入用绿色，支出用中性深灰，危险用红色，警告用琥珀色。[人工]

## 6. 固定栏与浮层

- **M23** 底部固定区域只能使用 `ErpMobileActionDock`、`ErpSubmitBar` 或底部导航，功能页面不得自己写 `fixed … bottom-*`。[lint]
- **M24** 固定栏要为安全区和软键盘留出空间（使用现有的视口与安全区服务）；有浮层打开时隐藏底部栏；页面内容底部要留出足够空间，保证最后一行能完整滚出来。回到顶部按钮不得遮挡内容。[人工]
- **M26** 一行最多并排 2 个按钮（1 个主操作加 1 个次操作）；有 3 个以上操作时，保留 1 个主操作，其余收进「···」打开的底部操作面板。纯图标按钮必须有 `aria-label` 或 `title`，收进操作面板后要显示文字。[人工]
- **M27** 按钮进入加载状态时保留原有宽度（`Button loading`），不得因为把文案换成「保存中…」而让按钮变宽变窄。[人工]
- **M25** 浮层：简短确认用居中对话框，少量选项用底部面板，大表单和搜索用全屏页面。[人工]

## 6.1 页面结构

- **M28** 业务页面（`src/features/*/pages/*.tsx`）不调用 `useErpPhone()`，不写「手机一份、电脑一份」的分支。手机和电脑两种布局由模板决定：列表页用 `ErpListPage`，详情抽屉用 `ErpRecordDetail`，开单页用 `ErpMobileWorkflow`。还没迁移的页面登记在 `scripts/mobile-rules-allowlist.json` 的 `pageViewport` 里，每项写明原因和对应任务；页面迁移完成后必须从清单里移除，否则检查失败。[lint]

## 7. 验收

1. `npm run lint`：包含本文所有标 [lint] 的规则。
2. `npm run test:mobile-rules`：需要先启动本地预览，命令是 `ERP_MOBILE_QA_PORT=3020 python3 scripts/mobile-preview-server.py`。脚本会在 320 和 390 两个宽度下检查全部业务页面，覆盖本文所有标 [浏览器] 的规则。确有合理原因的例外，登记在 `scripts/mobile-rules-allowlist.json` 里并写明原因。
3. **人工**：按第 3、4 节逐条核对，并附上 390 宽度的截图。
4. **真机**：浏览器模拟不能代替真机。iPhone Safari / 主屏幕模式下的软键盘、安全区、横屏和摄像头，发布前都要在真机上确认。
