# 核心型号行情参考：实施与边界

行情参考只维护核心型号的门店基础报价，不是库存成本或成交价。不分新旧、成色、质保、盒子或显存，也不再提供商品专属定价；同一核心只有一套当前回收/销售参考价。

完整核心型号必须保留 RTX / GTX / RX / ARC 前缀。大小写和型号内空格统一归一：`RTX4070TI`、`rtx4070ti`、`RTX4070ti`、`RTX 4070 Ti` 均为 `RTX4070TI`，ID 均为 `GPU-NVIDIA-RTX4070TI`。裸 `4070ti` 不自动猜测前缀；TI、SUPER、D、D V2 等仍为独立型号。该规则仅处理核心型号，不修改库存 SN 或其他业务字段的大小写。

## 范围与实施顺序

1. 增加稳定商业核心 ID（例如 GPU-NVIDIA-RTX5090）；RTX5090D、D V2、Ti、SUPER、RX 后缀独立。识别歧义不自动关联。
2. 录入只有完整核心型号与基础价格，保留维护人和可选截止日期。不再要求填写报价来源；表单去掉来源输入，历史已填写的来源保留。删除报价范围分段、商品选择和全部货况输入。
3. 基础价以 coreId 唯一，统一大写后再判重；更新追加完整门店日期历史。缺报价用 null，真实零保留。
4. 只匹配有效核心基础价；歧义、过期、旧报价及历史商品专属报价不自动套用。
5. 彻底移除普通行情更新的库存预计售价传播。外部价格同步接口仍是独立明确动作，不混入行情编辑。
6. 旧记录保留，编辑时明确确认重新关联；旧价格历史保留但标识为旧条件，不能拼入新条件趋势。
7. 复用现有行情列表、Dialog、Select、金额输入、详情与手机列表模板；补充筛选、CSV 和导入适用条件。
8. 验证 DTO、权限脱敏、重复导入、原子失败、价格保护、匹配优先级及 375/390/430/1440px。

## 存储与回滚

首期沿用 gpu_market_quotes JSONB 增量持久化，不新建平行集合或重写商品身份。核心 ID 由标准商业型号生成并保存到确认后的报价，不生成虚假商品 ID；商品关联通过真实 products 主键验证。未确认旧记录不批量回填。开发阶段只通过已登录网页只读核对生产库存；后续按用户明确授权发布构建产物，验收不创建测试报价或修改生产库存。

## 不做

自动溢价、自动市场抓取、自动修改库存售价、历史账务修正、CPU/硬盘行情改造、商品专属报价。基础价不代表任何特定实物必然成交价格。

## 后续使用

只维护核心基础价。具体商品的成交差价由开单时决定，不增加另一套行情报价。旧记录保留并需明确转换为核心基础价，遇同核心冲突先确认价格，不自动合并或覆盖。首期核心 ID 是商业型号的稳定标识，不是芯片裸片编号，也尚未建立独立核心档案管理页。
