# 库存上线前收尾

范围：型号汇总全局排序、手机型号行、行情风险身份展示与详情、库存分类读取一致性。沿用现有查询、权限、详情抽屉和业务提交链路。

## 执行计划

1. 使用现有表格列访问器对完整型号结果排序，再分页；切换排序回到第一页，默认显示总数量降序。
2. 手机型号行保留完整名称，省去名称中已包含的重复规格，将查看单卡放在数量之前，标题继续打开出入明细。
3. 行情风险显示完整型号和 SN，打开库存详情后关闭仍留在风险视图，保留筛选、搜索和页码。
4. 库存列表、详情、汇总和风险读取使用同一个类别优先级，SQL 关联限制同租户和门店；不猜名称、不写回历史数据。
5. 补分类缺失／冲突、权限排序回退、跨页排序、长身份与风险详情返回回归；手机验收 320／390，桌面及平板验收 768／1024／1440。
6. 运行 lint、test、mobile-rules、build；记录截图及剩余人工核对项，本任务不部署。

## 历史分类核查

`npm run inventory:categories:audit` 输出只读 JSON 核查报告，需要明确配置审核数据库。脚本独立于应用初始化；数据库会话和事务均强制只读，不运行迁移、不生成业务日志、不输出 SN 和金额。每条差异包含库存 ID、商品 ID、原分类、关联商品分类、展示分类和待人工核对原因。

已明确关联且商品分类有效的记录由读取投影修正展示，原事实保留。缺少商品档案、档案类别无效、或双方填了相同错误类别的情况，需要门店确认；清单不会凭 CPU / 外设等名称自动猜改。

生产环境报告须在获准的发布或审核窗口执行；iPhone Safari / 主屏幕的键盘、扫码和返回体验仍需真机验收，浏览器模拟不替代真机。

## 完成与验收

- 型号使用现有 TanStack 表格列排序完整结果后再分页，权限隐藏列不能继续控制排序，切换排序回到第一页；数量、金额、日期访问器沿用现有定义。
- 手机查看单卡位于身份和数量之间，删除重复底部操作行；只省去名称已包含的规格，不推断或补写商品事实。标题和图片仍打开出入明细。
- 手机行情风险完整显示名称及 SN，复用库存详情抽屉；关闭后保留风险视图、分类、搜索及页码。桌面风险表格结构未变。
- 分类列表、详情、汇总、风险及出入明细读投影已统一；SQL 商品关联同时约束租户和门店。集成测试确认查询与分类核查前后原始库存 JSON 不变。
