# 商品品牌字典

## 数据与规则

- 商品分类、商品品牌、GPU 厂商、核心型号和显存规格各自独立；品牌跨商品分类复用。组装拆卸仍是业务操作，不是分类。
- 预置 52 个常见硬件品牌，标准目录在 `src/data/productBrandCatalog.ts`。门店扩展使用 `gpu_product_brands`，主键为 `(tenant_id, store_id, id)`。
- `ProductBrandRecord` 保存稳定 ID、显示名、别名和维护人。NFKC、大小写、空格与点/横线/下划线归一后精确匹配；不从 NVIDIA / RTX 等核心信息猜商品品牌，不做模糊历史归属。
- `ASUS/asus/华硕` 指向同一品牌；显示统一名，所有别名均可搜索。品牌名称和别名不得占用其他品牌的身份。维护界面支持新建与补充别名，不提供删除/重命名入口。
- 商品增加可选 `brandId`。新建表单必须选择品牌，后端也验证品牌 ID/名称一致性。兼容旧客户端明确写入已知别名；未知名称需先创建品牌。CSV 导入的未确认旧品牌仍显式保留。
- 搜索只扩展品牌身份信息；型号后缀规则、SN/库存编号、分类、状态和资金算法保持既有语义。行情继续按核心基础价格，不建立品牌专属报价。

## 历史商品确认

- 商品库 → 页头「品牌管理」（手机在「更多操作」）→「历史匹配」。按原品牌分组，展示真实商品名称及精确匹配建议；未匹配项由维护者选定品牌。
- 点击「确认绑定」后调用专门的元数据动作，一次最多 200 款。只增加商品 `brandId`，保留原 `brand`、`name`、价格、库存、采购/销售历史和行情记录。
- 提交带原品牌值；原值改变、商品不存在、重复商品、已绑定到其他品牌或已知别名被分配给其他品牌时，整批拒绝。确认记录写入操作日志，日志和响应不包含商品价格。
- 品牌读标签与筛选通过字典解析，旧商品原文保留供核对；绑定可用于库存筛选，不直接改写库存档案。
- 本次没有自动绑定生产旧商品，也没有连接生产数据库。

## 接口与权限

| 接口 | 用途 |
| --- | --- |
| GET `/api/product-brands` | 读取品牌目录与维护资格；只加载小字典 |
| GET `/api/product-brands/legacy-matches` | 按需读取未绑定商品的匹配建议 |
| POST `/api/product-brands` | 新建品牌 |
| POST `/api/product-brands/:id/aliases` | 补充别名 |
| POST `/api/product-brands/bindings` | 确认历史商品归属 |

查看目录要求商品库、库存或采购/销售开单权限；历史匹配要求商品库权限。维护沿用核心目录的老板/权限管理资格，历史绑定同时要求商品库权限。所有写入受现有 CSRF、串行事务锁、幂等与门店隔离保护，只保存字典、明确商品与新增日志的增量补丁。

## 迁移与恢复

`server/migrations/011_product_brand_catalog.sql` 是新增表与索引的迁移，版本 `product-brand-catalog-v1`；初始化程序使用同一结构。不改写旧数据。回滚代码时保留新增表和可选品牌 ID，旧版本仍能读取原商品名称；人工绑定的恢复应依据日志和部署前备份，不能删整张商品表。
