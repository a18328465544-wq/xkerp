# V2 手机扫码解码

所有入口继续复用 `src/components/common/ErpBarcodeScannerDialog.tsx`：库存查找、检测质检 SN、销售出库核验、组装拆卸。`onDetected(code)` 和原有单次识别后关闭行为保持一致；扫描仅回填当前输入/草稿，库存与出库仍由既有服务端接口最终核验。

## 引擎与资源

### 取景窗口（2026-10-09）

- 手机与桌面共用紧凑弹窗，不占满手机屏幕。相机预览为 16:9，中央引导框为 3:1、宽度 82%；共享 `--erp-scanner-*` Token 管理，不在各业务入口复制尺寸。
- 预览使用 `object-fit: cover` / `object-position: center`，让浏览器返回的竖向、4:3 或横向视频都居中铺满 16:9 取景窗，避免条码对准框落在黑边上。竖向画面仅在显示时裁去上下多余部分；CSS 预览裁切不得传到解码层，识别继续读取完整源画面、保留原条码白边与二维码兼容，不改变识别队列、会话归属或出入库逻辑。
- 准备中与权限失败有独立状态；相机失败时隐藏引导框，保留重试、图片识别与手机手工输入。弹窗沿用共享安全区、键盘视口和内部滚动规则。
- 本地 Vite 可打开 `/scripts/fixtures/barcode-scanner.html?preview=frame`、`?preview=portrait` 或 `?preview=denied` 检查横向/竖向源画面及错误态。这是显式合成画面，不访问真实摄像头，也不作为真机扫码识别率证明。

- 原生 `BarcodeDetector` 支持全部请求格式时优先使用；能力查询失败、构造失败或格式支持不全时进入兼容引擎。
- 原生连续三个解码异常、单次解码超过 1.2 秒或持续 2.5 秒无结果时，当前会话切换为兼容引擎。单张图片无原生结果时立即尝试兼容引擎。
- 兼容引擎锁定 `barcode-detector@3.2.2` / `zxing-wasm@3.1.3`，通过 Vite 动态模块创建 Worker。版本匹配的 `zxing_reader.wasm` 是本站带内容哈希的构建资源，不使用库默认的公共 CDN 地址。
- 正常页面和正常原生扫码不加载 Worker/WASM。扫码画面最多 1280px 长边；视频串行解码最多约 8 帧/秒。兼容引擎初始化限制为 15 秒、单帧限制为 5 秒，失败后允许用户重试。
- `barcode-detector` / `zxing-wasm` 仅允许在共享组件适配层导入；业务页面不直接管理第三方引擎。

## 生命周期与失败处理

### 启动画面稳定（2026-10-12）

- 放大控件从打开时挂载，准备期间禁用；镜头切换按钮的槽位保留，无多个后置镜头时不可见、不可聚焦。相机、解码器和镜头枚举的完成不能增高正常弹窗或移动取景窗口。
- 相机启动与解码器准备分开管理。弹窗首屏即用不透明准备遮罩覆盖固定 16:9 取景窗口；解码器切换到 WASM 时不重新遮黑已经可用的相机。
- `barcodeCameraPreview.ts` 在 `play()` 前注册连续帧等待：支持 `requestVideoFrameCallback` 时不断重新注册，至少四个有效帧、画面尺寸连续稳定 300ms，随后跨两个页面绘制周期才就绪。尺寸变化、无效帧或停顿超过 500ms 会重新计数；旧浏览器还要求 `currentTime` 推进，不能用重复绘制冒充新画面。`loadedmetadata`、`play()` 完成或单帧均不单独作为就绪证据，超时不能直接揭开遮罩。此条件检查启动尺寸，不保证物理对焦完成。[帧回调依据](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)
- 准备期间视频元素自身 `opacity: 0`，不仅依靠遮罩遮住相机合成层；保持挂载和播放，不使用 `display: none` / `visibility: hidden`。默认 1× 不建立无意义的 `scale(1)` 合成层，仅数字放大时设置 transform；切镜头立即撤销画面就绪。
- 相机画面等待最多 8 秒，超时显示重试/图片识别提示，不能直接曝光未就绪画面。镜头更换、关闭、所属任务失活取消帧回调、绘制等待与计时器，释放相机；相机失败不阻止已有图片识别与手动输入。
- `npm run test:barcode-startup` 在本地合成相机覆盖授权等待、慢解码器、首帧迟到/无效、旧浏览器、延迟镜头枚举、切镜头和启动中关闭，检查 320/390/1440px 的窗口/预览/控件位置不跳动。仍需 iPhone Safari/主屏幕模式及 Android 实体设备验收，合成首帧和尺寸测试不等于物理对焦验收。
- 本地最终验收：新增 7 个首帧等待单元场景和 1 个布局契约；启动 15 场景、相机控件 20 场景、实际 WASM 解码 32 场景通过。全量测试 1777 通过、37 数据库条件测试跳过、0 失败；lint、构建、手机 38 页 × 320/390px 规则通过。库存/出库/质检页在 390/1024/1440px 未打开扫码时前后截图一致。本轮没有合并、上传或部署，实体手机仍待验收。

#### 连续帧跟进修复（2026-10-12）

- 用户反馈已发布版本仍闪跳。代码复现确认：原等待器只有一次有效视频回调，之后两次页面绘制即可揭开遮罩，不能证明相机连续输出稳定。这次按上述连续帧条件和视频自身透明度保护修复；不新增相机接口、解码引擎或业务动作。
- 新增/加强单元测试覆盖单帧后重复绘制、晚到的竖横尺寸变化、元数据尺寸变化、短时间密集回调、暂停后重新稳定、旧浏览器播放进度，以及默认无 transform / 未就绪透明度契约。合成相机持续产生视频帧并在关闭时停止，避免静态画布冒充连续相机帧。
- 本地验收：lint（含类型检查）、构建、全量测试 1804 通过 / 37 数据库条件测试跳过 / 0 失败；启动 18 场景、控件 20 场景、实际 WASM 解码 32 场景通过；本地构建产物库存入口 3 场景通过（拦截本地 API，无真实业务写入）。手机规则 38 页 × 320/390px 通过，390/1440px 启动画面与竖向取景截图已检查。
- 未合并或部署；iPhone Safari / 主屏幕模式实体相机闪跳仍需发布后真机验收，不能把本地合成视频结果当作真机效果证明。

关闭、卸载、任务失活、重试、手动录入或识别成功都会终止对应 Worker 并释放已获得的相机轨道。晚到的权限请求和识别结果不属于新会话，不能回填、关闭新的弹窗。图片与视频共用同一串行解码队列。

相机需要 HTTPS（开发时 localhost/127.0.0.1 可用）以及浏览器授权；相机权限拒绝不阻止图片识别。JPG / PNG / WEBP / BMP 图片最多 12MB，只在设备端读取、缩放和解码，不上传相机画面或条码照片。无有效条码、加载失败及权限拒绝都有操作提示，手机保留手工 SN/编号输入。

显卡标签可能有 SN、P/N、商品码等多个条码。解码器只返回扫描内容，不在通用组件里猜测品牌 SN、不删除前导零、不自动改写大小写；现有领域核验继续判断是否属于当前库存/单据。未来连续扫码与多码选择应有单独的交互和业务验收。

### 近距离对焦与放大（2026-10-11）

- 申请后置 1920×1080 ideal 视频，实际尺寸以浏览器返回为准；解码长边仍最多 1280px、串行约 8 帧/秒，不扩大 Worker 数据量。
- 参考 [W3C Image Capture（2025-04-23），9.2–9.4 节](https://www.w3.org/TR/image-capture/)：按轨道实际 `getCapabilities()` 检查 `focusMode`/`zoom`，支持才申请连续对焦。浏览器拒绝或不提供能力时继续普通扫码，不展示虚假的点击对焦/微距按钮。
- 共享 `ErpSegmentedControl` 提供 1× / 1.5× / 2×。相机变焦受范围/步长约束，以 `getSettings()` 核验；被忽略、拒绝或范围不足时使用剩余倍率的中心裁剪。预览和解码采用相同中心倍率，先裁剪再缩放以保留标签像素，不能把失焦图像恢复清晰。
- 数字放大时每四帧仍有一帧读取完整源画面，保留原有边缘条码白边、二维码识别与回填行为。变焦中暂停新帧，之后留 250ms 的对焦稳定窗口；不按固定清晰度阈值丢弃条码，避免误伤浅色/低对比标签。
- 摄像头授权后枚举镜头，仅当前相机和明确后置标签可切换，前置/未知标签不猜测为微距；只有多个候选时展示「切换镜头」。选择仅记在当前网页内存，不存设备 ID 到服务端或持久化存储。镜头更换、关闭、失活仍释放原轨道；设备 ID 失效可回到默认后置，权限拒绝不可绕过。
- 保留图片本地识别和手工输入，不上传画面，不改入库/出库/业务接口。模糊时先拿远，再放大；系统相机拍照后「从图片识别」仍是兜底。
