# ERP UI 设计规约

## 1. 目标与适用范围

这套规则适用于所有新页面、旧页面改版、弹窗、抽屉、表格、导航和经营看板。目标不是“每页看起来差不多”，而是让用户在库存、采购、销售和财务之间切换时，始终获得同一套信息层级和操作反馈。

高密度页面额外遵循 [`COMPACT_LAYOUT_RULES.md`](./COMPACT_LAYOUT_RULES.md)：默认收起介绍性副标题和表格说明，把首屏空间留给真实数据、筛选和下一步操作。

设计关键词：

- 浅色、克制、清晰：白色内容面板 + 浅灰画布，减少装饰性渐变和大面积纯色。
- 数据优先：优先展示数量、金额、状态、时间和下一步操作，避免无意义留白。
- 语义颜色：颜色只表达业务含义，不用颜色装饰普通文本。
- 可追溯：单号、SN、账户、时间和操作入口要能直接定位。
- 可操作：每个按钮、筛选、标签和图标都必须有明确行为或明确的静态状态。

## 2. 设计源和实现源

实现时按以下顺序取值：

1. 本文的语义规则。
2. src/index.css 中的 ERP CSS 变量和 Tailwind 主题。
3. src/components/shared/index.ts（按 actions/layout/forms/feedback/overlays 分类出口聚合，底层实现位于各职责文件，ui.tsx 仅保留兼容重导出）中的 PageShell、Card、Button、Badge、Modal、StatCard、表单类常量。
4. 现有模块组件的局部布局。

禁止在新页面里另起一套颜色、圆角、阴影和控件高度。确实需要新增 token 时，先在本文和 src/index.css 中登记，再使用。

## 3. 颜色系统

### 3.1 基础色

| 语义 | 当前 token | 用途 |
| --- | --- | --- |
| 页面画布 | erp-page-bg / slate-50 | 页面最外层背景 |
| 内容卡片 | erp-card-bg / white | 卡片、表格、弹窗主体 |
| 容器边框 | erp-border / slate-200 | 卡片、分割线、输入框外框 |
| 弱分割线 | erp-border-soft | 表格行、卡片内分组 |
| 主文字 | erp-text-main / slate-900 | 标题、金额、关键字段 |
| 次文字 | erp-text-secondary / slate-600 | 正文、表格内容、导航 |
| 辅助文字 | erp-text-muted / slate-400 或 slate-500 | 提示、占位、时间、说明 |

### 3.2 业务色

| 语义 | 默认颜色 | 用途 |
| --- | --- | --- |
| 主操作/链接 | blue-600 / erp-primary-blue | 主按钮、链接、当前导航、可点击单号 |
| 成功/收入/利润 | emerald-600 或 erp-profit-green | 已完成、收入、正向变化、健康指标 |
| 提醒/待处理 | amber-600 / erp-warning-orange | 待处理、库存积压、需要关注 |
| 风险/支出/破坏性操作 | rose-600 / erp-loss-red | 负数、风险、删除、失败、支出 |
| 中性 | slate-500 | 未选中、无变化、普通辅助状态 |

规则：

- 正数和负数必须用语义颜色配合文字，不能只依赖颜色。
- 蓝色只代表可操作或主品牌，不把所有数字都染成蓝色。
- 背景使用 50/100 级浅色，文字使用 600/700 级可读色，避免浅色文字放在白底。
- 同一指标的主值、比较值和状态必须保持同一语义色，不要一张卡里出现互相矛盾的颜色。

## 4. 字体与信息层级

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 页面标题 | 20–24px，700–800 | 模块名称，例如库存中心、资金调拨 |
| 区块标题 | 14–16px，700 | 卡片标题、表格标题、步骤标题 |
| 正文 | 14px，400–600 | 表单值、表格正文、主要说明 |
| 标签 | 12px，500–600 | 字段名称、筛选项、状态辅助信息 |
| 辅助信息 | 11–12px，400–500 | 单位、时间、说明、空状态 |
| 数字/单号 | SF Mono 或 JetBrains Mono | 金额、数量、单号、SN、时间和百分比 |

规则：

- 金额、数量、百分比、单号和 SN 使用等宽字体并保持右对齐或可识别的固定宽度。
- 已选择的日期、日期范围、时间和可比较的数字状态使用等宽字体；占位文案、中文说明和自由文本保持常规无衬线字体。
- 中文标题不要全大写，不使用过度加粗来代替层级。
- 页面标题下最多放一行短说明；长说明必须截断、折行或放入帮助提示。
- 一个卡片最多有一个最强视觉主值，避免多个同等大小数字互相竞争。

## 5. 间距、圆角与阴影

- 页面主内容使用 16–24px 外边距；桌面端主画布最大宽度统一由 `--erp-page-max-width` 控制，当前值为 1720px。
- 卡片默认内边距 16px；卡片之间默认间距 16px；同一表单组之间默认间距 12px。
- 内容区优先使用 gap-3/gap-4/gap-6，不用随意写出大量单独 margin。
- 内容卡片使用 rounded-xl；小控件使用 rounded-lg；状态徽章使用 rounded 或 rounded-md。
- 阴影只用于层级：卡片使用轻微 shadow-sm，弹窗/浮层使用 shadow-xl；不要给每个文字或按钮单独加阴影。
- 页面不能通过增大 padding 来制造“高级感”；信息型 ERP 页面优先保证可见字段数量。

## 6. 页面骨架

标准页面由以下顺序组成：

1. 应用工具栏：工作区标签、全局搜索、通知、账号。
2. 模块导航：一级模块导航和模块二级导航，不能重复占位。
3. 页面标题区：标题、短说明、主操作。
4. 概览区：统计卡或风险提示，数量通常 3–8 张。
5. 主要工作区：表单、图表或主表格。
6. 辅助区：分析、提醒、最近记录或操作说明。

页面标题已由模块二级导航承载时，使用 PageShell 的 hideHeader，避免出现两个相同标题和大片留白。

应用壳层固定在视口内：工作区工具栏和侧边导航不得随业务内容滚动，主内容区使用独立的纵向滚动容器；侧边导航自身的长菜单才允许内部滚动。

## 7. 导航规则

### 7.1 一级导航

- 一级导航表达业务模块，不表达当前页面的全部动作。
- 标签数量多时采用浏览器式横向堆叠/压缩：保留当前标签完整显示，其余标签按可用宽度缩短，使用横向滚动或更多菜单承载溢出。
- 默认背景透明或接近画布；悬停、选中和键盘聚焦时再显示浅色背景或下划线。
- 固定/置顶按钮只有在确实有持久化行为时才显示；没有行为的图标必须删除。

### 7.2 二级导航

- 桌面端一级模块只占侧边栏入口；二级页面通过靠近当前入口的悬浮面板展开，避免侧边栏被长菜单撑高并保留工作区宽度。
- 悬浮面板直接从二级入口列表开始，不重复渲染父模块名称、图标或“共 N 项”计数；父模块身份由侧边栏当前态承担。
- 悬浮面板支持悬停、点击和键盘聚焦打开；鼠标离开后保留短暂缓冲，允许从入口移动到面板，避免误关闭。
- 面板内当前项使用浅蓝背景与蓝色文字，未选中项使用 slate-600，悬停时使用 slate-900；点击路由后立即关闭。
- Escape、面板外点击和路由切换都必须关闭悬浮面板；面板使用统一 popover 层级、边框、圆角和阴影。
- 移动端不使用悬浮定位，改为侧边栏内的可展开二级列表，保证触控热区和可访问性。
- 导航顺序按业务流程排列，切换后保留页面临时状态；不要用“更多”隐藏常用入口。

### 7.3 侧边栏

- 侧边栏是一级模块入口，不重复显示当前模块的所有二级页面。
- 当前模块使用浅蓝背景和蓝色文字；非当前模块保持白底。
- 菜单项图标、文字和箭头必须垂直居中，点击热区不小于 40px。
- 桌面展开态侧栏宽度固定为 12rem，只为图标、名称和箭头保留必要空间；不得用空白撑宽。收起态保持 5rem，移动端按视口宽度适配。
- 移动端导航抽屉不得继承桌面收起状态：抽屉宽度最多 22rem 且不超过视口减 16px，一级/二级菜单文字始终可见，二级链接热区不小于 44px。
- 侧边栏底部的资金池、经营评分等摘要卡必须并排且不遮挡菜单；空间不足时折叠摘要内容，不制造大块空白。

## 8. 统计卡与经营指标

- 统计卡默认使用白底、边框、轻阴影；同一组卡片高度一致。
- 卡片结构固定为：标签 → 主值 → 比较值/单位 → 可选图标。
- 主值必须来自真实状态计算；上一天/上一周期数据必须真实可追溯。
- 无数据显示 0、暂无记录或明确空状态，不显示伪造的上涨百分比。
- 数值颜色按照业务语义匹配：收入/利润绿色、支出/损失红色、风险橙色、库存/中性蓝或黑色。
- 卡片在 1440px 下优先一行显示；小于 1024px 时允许两列或横向滚动，但不能压缩到无法阅读。

## 9. 表单与按钮

### 9.1 控件

- 普通控件默认高度 40px，紧凑筛选控件 36px，表格内编辑控件 36–38px。
- 普通表单输入与表单内搜索输入必须共用 `erp-form-control` / `erp-search-control` 的高度、边框和 8px 圆角；业务代码使用 `formControlCls`/`controlCls`，不要再拼接 `h-9` 或 `h-10`。复合选择器使用 `erp-control-shell`，内部按钮只负责交互，不另起一套尺寸。
- `DropdownSelect` 的普通尺寸与 `erp-form-control` 同为 40px，紧凑尺寸必须同时使用 `size="sm"` 与 `compactFormControlCls`（36px）；高度由共享 token 强制控制，禁止用 `className` 中的 `h-*` 改写普通下拉尺寸。
- `SearchInput` 默认 40px；只有筛选/表格工具栏明确传入 `compact` 或由 `FilterBar`/`TableToolbar` 统一压缩时才使用 36px。
- `FilterBar` 内的搜索和筛选控件可以按密度规则压缩到 36px，但不能把这种紧凑样式带入弹窗或主表单。
- 控件边框使用 slate-300；聚焦使用 blue-500 边框和浅蓝 ring。
- 字段标签 12px，字段值 14px；必填项用红色星号，不用整段红字。
- 数字输入必须设置 min/max/step（适用时），提交前再次校验，不能只依赖浏览器原生校验。
- 只读字段使用 slate-50 背景并明确不可编辑，不要伪装成可输入状态。
- 下拉选择默认使用 `DropdownSelect`（由 `src/components/shared/forms.tsx` 统一提供），禁止在新页面直接使用原生 `<select>`。组件统一提供 8px 圆角、选中勾选、蓝色聚焦态、键盘上下选择和点击外部关闭；`FilterSelect` 仅作为紧凑筛选场景的兼容封装。
- 新增业务页面优先从 `src/components/shared` 或对应职责出口引入基础组件，从 `src/components/domains/<domain>` 引入同域页面组件；`src/components/ui.tsx`、各平铺页面文件仍是兼容入口，不再新增第二套同名实现。

### 9.2 按钮

| 类型 | 视觉 | 使用场景 |
| --- | --- | --- |
| Primary | 蓝底白字 | 当前区域唯一主要提交/创建动作 |
| Secondary | 白底边框 | 导出、取消、次要动作 |
| Ghost | 透明 | 表格行内、轻量切换、关闭 |
| Danger | 红色语义 | 删除、作废、破坏性操作 |
| Warning | 橙色语义 | 需要注意但不属于破坏性的操作 |

- 一个区域通常只有一个 Primary 按钮。
- 所有新增或迁移的按钮 DOM 必须经过 `ButtonBase`；业务代码禁止直接使用 `ButtonBase`，按语义选择 `Button`、`IconButton`、`TextButton`、`ToggleButton` 或 `PressableCard`。尚未迁移的原生按钮由只降不升的基线约束。
- `Button` 的 `md` 用于普通 40px 操作，`sm` 用于 36px 紧凑工具栏，`xs` 仅用于表格或密集行内操作；图标按钮使用 `IconButton` 的同名尺寸，不再使用 `iconXs/icon/iconLg`。
- 组件默认输出 `type="button"`；只有真正提交表单的主按钮显式传入 `type="submit"`，避免按钮迁入表单后意外提交。
- 异步操作统一使用 `loading` 和 `loadingText`，组件负责禁用重复点击、加载图标及 `aria-busy`，业务页面不再手写一套加载按钮。
- `Button`/`IconButton` 的 `className` 只允许布局类（如 `w-full`、`flex-1`、外边距）；颜色、边框、高度、内边距和圆角必须由 `variant`、`size`、`shape` 表达。
- 按钮文字使用动词：新增、提交、保存、导出、查看、删除。
- 异步提交时显示加载或禁用状态，成功/失败必须有通知。
- `IconButton` 必须提供 `label`，组件会同时生成 `aria-label` 和默认 `title`；不能只靠用户猜图标。
- 删除、批量修改、冲销、确认出库等不可逆动作必须使用 ConfirmDialog。
- `npm run lint:ui` 会阻止漏写原生按钮 `type`、视觉样式逃逸、废弃尺寸和新增原生按钮；存量原生按钮以 `scripts/ui-button-baseline.json` 为只降不升的迁移基线。

全局命令搜索（顶部快捷搜索）可以保留独立的 40px / 12px 圆角样式；业务表单和列表搜索必须使用 `SearchInput`，不要把顶部命令搜索样式复制到业务筛选框。

## 10. 表格、筛选与分页

- 业务表格优先使用 DataTable/TanStackDataTable；只有结构非常特殊时才使用原生 table。
- 表头使用浅灰底和 11–12px 字号；正文 12–14px，行高保持紧凑但可扫描。
- 金额和数量右对齐，时间/单号使用等宽字体，文本列按业务重要性排序。
- 首列保留核心身份字段（商品/SN/单号），操作列固定在右侧或保持稳定可见。
- 复杂表格必须提供空状态、加载状态、错误状态、列设置或合理的默认列。
- 筛选栏按“范围/账户/状态 → 搜索 → 高级筛选 → 导出/刷新”的顺序排列。
- 修改筛选条件后分页自动回到第 1 页；页大小变化也回到第 1 页。
- 表格数据为空时不能只显示空白大区域，应提供原因和下一步操作。
- 空状态默认保留可读的面板高度；嵌套在统计卡、图表或紧凑 DashboardSection 中时使用 `density="compact"`，避免重复占用大块留白。
- 允许横向滚动时，滚动容器必须有明确边界，不能让页面整体被无意撑宽。

## 11. 卡片、抽屉和弹窗

### 11.1 卡片

- 卡片只承载一个清晰主题：统计、表单、列表、图表或提醒。
- 不把不同业务流程硬塞进同一张卡；需要分组时使用标题和弱分割线。
- 卡片标题、操作和内容顶部对齐，操作按钮不漂浮在无关空白处。

### 11.2 弹窗

- 弹窗用于短流程、确认和局部编辑；大数据表或多步骤流程使用依附当前页面的工作区/抽屉。
- 遮罩应能识别当前上下文，主体最大高度不超过视口并在内部滚动。
- 右上角统一关闭；关闭未保存内容前必须提示或保留状态。
- 标题、说明、正文、底部操作顺序固定；主操作放右侧，取消放左侧。
- 弹窗不应因切换其他标签而意外销毁，除非用户明确关闭。

### 11.3 抽屉/工作面板

- 抽屉用于库存详情、进出明细和辅助编辑，必须依附主页面，不覆盖全局导航。
- Workspace Tabs 是全局最高应用层级；日期、选项和其他浮层统一使用低于 Tab、高于弹窗/抽屉的 `--erp-layer-popover`，普通模态弹窗使用 `--erp-layer-modal`，抽屉及其遮罩使用 `--erp-layer-drawer` / `--erp-layer-drawer-backdrop`，不能覆盖、模糊或拦截 Tab 栏。业务页面不得直接写裸 `z-*` 层级。
- 顶部固定标题和关闭入口，底部固定主要操作，中间内容独立滚动。
- 页面切换时保留已打开抽屉状态；抽屉数据必须标明来源单据和当前状态。

## 12. 图表与数据可视化

- 图表必须有标题、时间范围、单位、图例和空数据状态。
- 时间范围切换必须真正改变数据，不只改变按钮选中样式。
- 颜色语义与统计卡一致；收入、支出、净现金流不能使用相同颜色。
- 图表旁边提供可读的关键汇总，不能把精确数值只放在 hover tooltip 中。
- 经营趋势、库存风险和资金健康度都必须标注计算范围和更新时间。

## 13. 响应式与可访问性

- 设计检查至少覆盖 1440px 桌面、1024px 平板和 390px 窄屏。
- 窄屏优先保证标题、主操作、搜索和关键字段可用；次要字段可折叠、横向滚动或进入详情。
- 不允许固定定位元素遮挡主操作、导航或底部账号区。
- 键盘可以访问所有按钮、标签、输入和关闭入口；焦点状态清晰。
- 表单控件要有 label 或 aria-label；图标按钮和表格复选框必须可读。
- 颜色不是唯一信息来源；状态同时使用文字、图标或徽章。
- 动画只用于状态过渡，不使用影响阅读的持续闪烁。

## 14. 设计稿复刻流程

接到截图或设计稿时按以下顺序执行：

1. 先识别页面骨架、导航层级、主信息区和操作路径。
2. 把截图中的静态数字映射到真实数据字段，确认空数据和权限状态。
3. 先复刻宽度、层级、间距和信息密度，再处理图标、颜色和细节。
4. 对照 1440px 截图检查首屏；再检查窄屏是否出现遮挡、溢出和不可点击。
5. 验证所有按钮、标签、筛选、分页、导出和关闭行为。
6. 将新增 token 或组件规则回写本文和 ui.tsx/index.css，不在页面里留下孤立样式。

## 15. UI 反模式

以下做法禁止进入新代码：

- 用固定数字、固定百分比或静态示例卡片冒充真实指标。
- 为了“看起来像截图”复制不可操作的按钮、无效标签或空白占位。
- 同一项目同时使用多套蓝色、圆角、按钮高度和弹窗关闭方式。
- 一级导航和二级导航重复展示同一批入口。
- 用大面积 padding、空卡片或隐藏字段解决布局问题。
- 用颜色覆盖数据语义，或把所有链接、数字都染成蓝色。
- 在页面组件里直接更新库存、账户余额、利润或 SN 状态。
- 用原生 alert/confirm、无标题图标按钮或没有错误提示的异步操作。

## 16. UI 交付检查清单

- [ ] 页面使用统一画布、卡片、边框、圆角、阴影和字体。
- [ ] 页面标题、二级导航和主操作没有重复或留白占位。
- [ ] 主指标来自真实数据，并有上一天/上一周期对比或明确空状态。
- [ ] 所有可见按钮、筛选、标签、分页和关闭入口都能工作。
- [ ] 表格有空状态、加载/错误态、稳定操作列和合理分页。
- [ ] 弹窗/抽屉不遮挡全局导航，未保存内容不会静默丢失。
- [ ] 1440px、1024px、390px 三个尺寸均可用。
- [ ] 键盘焦点、aria-label、状态文字和颜色语义均已检查。
- [ ] 视觉改动已补充渲染测试或手工验收记录。

## 17. 报表系统统一规范

报表页面统一遵循 [`docs/REPORT_UI_STANDARD.md`](./REPORT_UI_STANDARD.md)。标准顺序为“标题/操作区 → 报表页签 → 筛选区 → 指标卡 → 分析区 → 明细表 → 汇总说明”，统一复用 `ReportPageLayout`、`ReportActions`、`ReportFilterPanel`、`ReportMetricCard` 和 `ReportSection`。账户流水报表是当前基准实现，销售利润报表已迁移到同一骨架；后续报表不得自行拼接另一套标题、页签、筛选或卡片规范。
