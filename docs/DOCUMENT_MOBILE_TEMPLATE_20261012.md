## 共用规则

- `ErpDocumentRecordRow`：连续分隔行，无占位商品图；完整单号可换行，状态和数量分开，金额使用现有格式化和权限判断，往来对象、经办人、商品摘要、关联单据和时间保留。
- `ErpListPage` 的 `phonePresentation="documents"`：明确的筛选、新增和更多入口；搜索保持底部易触达；操作、刷新和每页条数收进更多，不与筛选混放。
- `ErpDocumentFilterSheet`：打开时复制已应用条件；编辑和重置仅改草稿；关闭丢弃；应用时一次提交完整条件，不逐字段重放旧闭包。重置保留搜索、排序和每页条数，应用后回第 1 页。
- `ErpRecordDetail`：关键信息、状态和金额 → 明细 → 折叠备注/附件；已有桌面详情通过 `desktopContent` 原样保留。
- `ErpDocumentActions`：一个主要动作及更多菜单；危险动作仍调用原业务确认窗口，没有绕过权限或确认。
- 财务统计最初放入更多中的「统计摘要」。后续七项 UI 收敛按用户新要求调整为两项核心指标加「更多指标」，保留原计算口径；详见 `UI_POLISH_20261012.md`。
- 账户流水及组装列表不增加只排序当前页的伪全局排序；采购关联库存数量明确标注「关联库存」，不冒充已入库数量。
- 行布局、字号、按钮和安全区域沿用现有全局 token、共享弹层及控件。
- `ErpListPage.phoneTask` 承担手机工作台的列表/任务切换和返回层；单页仅传入原核验内容、原关闭回调和查询入口。返回列表再打开同一单不重建扫码草稿。
- 协同订单详情复用原协同安排、关联单据和时间线节点，不复制第二套表单控制器；订单业务类型不充当金额。
- 提成列表以关联单号为身份，提成记录编号另作辅助字段；零元正常显示。列表和详情金额均沿用 `showProfit`，结算动作沿用老板权限和原确认窗口。
- 日结的月结锁定/最新异常在手机折叠区保留，账务体检及原锁定确认流程不变。
- 退货对账保留每类最多 100 条的原读取边界，并在更多中提示；没有将有限记录伪装成全量服务器分页。无全量排序接口的列表不新增手机排序入口。

- `npm run lint`：通过，包括前后端类型、未使用代码、架构及移动端契约检查。
- `npm test`：1819 项；1782 通过，37 跳过，0 失败。

- `git diff --check`：通过。
- 新增测试覆盖：单据行身份与零值、筛选草稿不触发原回调、草稿默认值、手机单主操作/危险操作折叠、桌面内容保留、无全量接口时不提供伪排序。
- 工作台新增回归测试：手机只呈现一个核验任务，不重复列表/扫码输入；返回后恢复列表；桌面双栏原节点和 SN 日期入口保留；返回处理委托共享模板。

### 浏览器验证

使用独立的本地合成数据服务，所有业务写入被拒绝，不连接生产数据库。
合成数据仅用来验收真实组件的显示与参数传递，不能证明生产余额、筛选 SQL 或真实单据已正确入账。

- 10 类列表分别检查 320、390、430 CSS px，共 30 组：数据完成渲染，页面根宽度没有横向溢出。
- 10 类详情在 390px 检查：单列结构，没有整页横向溢出；超长收入编号及大金额另在 320px 检查。
- 销售筛选：修改「未收款」后关闭，再打开仍为已应用的「全部收款状态」；修改草稿期间 URL 不变。
- 同时选择「未收款」「待出库」，应用后 URL 同时包含两项条件。
- 重置验收：应用前 URL 不变；应用后删除付款条件，保留 `keyword=4090`、`pageSize=50`、`sortKey=totalAmount`、`sortDirection=asc`。
- 收入详情「更多 → 冲销」仍打开原二次确认，未点击确认，未执行资金动作。
- 768/1024px 的采购、销售、收入、流水检查：未进入新手机单据布局，根宽度无横向溢出。
- 最终验收浏览器日志未发现页面运行错误。
